# Управление установкой

**Кандидат для стендовой проверки. Готовый production-релиз ещё не принят.**
Публичный bootstrap намеренно отключён после отзыва dsg1. Команды ниже относятся
к распакованному комплекту кандидата с проверенным SHA256SUMS, а не являются
разрешением использовать отозванный архив.

## Меню и режимы

`sudo bash setup.sh` открывает русское меню. Без терминала укажите `--mode`:

| Режим | Действие |
|---|---|
| `full` | Проверенное ядро, ds-guard и профиль сети |
| `kernel` | Только подготовка проверенного ядра |
| `tune` | Только профиль сети |
| `guard` | Только ds-guard для работающего ядра |
| `check` | Показать выбор версии и план без изменений |
| `status` | Показать службы, модуль, очереди, параметры и ошибки |
| `disable` | Остановить фильтрацию, запретить её автозапуск, вернуть сетевые значения |
| `remove` | Удалить изменения этой установки и восстановить сохранённое состояние |

Проверка `check` — это выбор подходящей версии; она не заменяет полный контроль
ресурсов, загрузчика и драйверов, который выполняется перед изменением.
`status` не проверяет клиентский VPN. Полная установка проверяет три локальных
слоя и HTTPS; `--health-command 'КОМАНДА'` добавляет проверку вашего приложения.
Проверка должна быть ограниченной по времени и не менять настройки системы.

`--kernel-policy prefer-xanmod` выбирает наибольшую проверенную версию XanMod
для текущей ОС и общего набора инструкций всех CPU. Если такого комплекта нет,
выбирается проверенный Ubuntu. `xanmod` запрещает fallback; `ubuntu` явно
выбирает Ubuntu; `keep` сохраняет работающее ядро. Более свежий выпуск upstream
не становится проверенным автоматически. Каталог обновляется вместе с
протестированным выпуском установщика; фонового обновления ядра нет.

Для Ubuntu 22.04 сейчас проверено Ubuntu 6.8.0-87; для Ubuntu 24.04 — Ubuntu
6.8.0-147 и отдельные XanMod 7.0.12/v2, 7.2.9/v3 с LIVEPATCH. Штатное XanMod
без LIVEPATCH нельзя сделать совместимым заменой одного модуля.
`--tuning keep` исключает настройку сети из полного режима.

Для текущих XanMod-комплектов известна несовместимость с загруженными
`vga16fb`/`vgastate`: этих драйверов в них нет. В таком случае предпочтение
XanMod переводится на совместимый Ubuntu до установки пакетов; режим «только
XanMod» завершается отказом. Даже VM без VGA-устройства может автоматически
загрузить эти модули в Ubuntu. Не следует отключать эту проверку ради перехода.
Другие отсутствующие драйверы останавливают подготовку после проверки состава
модулей. Уже установленные при подготовке пакеты остаются отражены в журнале
и могут быть удалены отдельным режимом; выбор загрузки сохраняется.
Автоматический fallback не понижает работающее ядро, включая номер ABI Ubuntu.
Суффикс `dsg1` в названии проверенных ядер сохранён: ядра не содержат nDPI;
исправленный модуль имеет отдельную версию `1.7.63880be7697-dsg2`.

Подготовка другого ядра устанавливает пакеты рядом с прежними и заканчивается
кодом 20. Работающее ядро не меняется, перезагрузка не запускается. Требуется
проверенный GRUB с сохранённым существующим fallback по стабильному ID, без
незавершённого одноразового выбора. Выбор следующей загрузки, проверка доступа
к консоли и сама перезагрузка остаются отдельным шагом. После загрузки нового
ядра повторите полный режим для проверки и активации ds-guard.

## Сетевой профиль

Профиль включает BBR, `fq` для новых интерфейсов, TCP Fast Open, MTU probing,
буферы TCP, очереди и conntrack с учётом памяти. Уже более высокие лимиты
буферов, очередей и conntrack не уменьшаются. Настройки применяются точечно;
общий `sysctl --system`, перезапуск сети и сброс firewall не выполняются.
Действующие qdisc и ограничения скорости не заменяются. Подготовленный размер
хеш-таблицы conntrack применяется при следующей отдельной загрузке модуля.

До изменения записываются прежние значения и собственные файлы. После него
проверяются значения, маршруты, правила, qdisc, TCP-слушатели, HTTPS и заданная
проверка приложения. Ошибка вызывает возврат. Процесс ограничен systemd;
при зависании восстановление начинается после остановки всей группы процессов.
Это не гарантирует сохранение доступности при любой аппаратной аварии или
отключении питания. Не следует считать эти параметры доказательством роста
скорости: для этого нужен отдельный замер реальной нагрузки.

## Отключение и удаление

Первый запуск сохраняет исходное состояние. Повторные запуски не подменяют
его последним установленным состоянием. Можно сначала посмотреть удаление:

```bash
sudo bash setup.sh --mode remove --plan
```

`disable` снимает собственные подключения к цепочкам фильтрации, останавливает
службы и таймер, блокирует автозапуск и восстанавливает сетевые значения.
Повторная установка через `full`/`guard` снова проходит проверки перед запуском.
Параметры ядра и модуль в памяти нельзя полностью вернуть простым удалением
файлов: livepatch не выгружается принудительно, для него нужна отдельная
плановая перезагрузка. Размер conntrack hashsize после его изменения при
загрузке также возвращается после загрузки с восстановленной конфигурацией.
Та же граница действует для BBR/conntrack, если эти модули впервые загрузились
при установке: профиль возвращается сразу, состав модулей — после перезагрузки.

`remove` восстанавливает сохранённые файлы/параметры и удаляет пакеты,
установленные собственными пакетными процессами. Для каждого такого процесса
ведётся отдельный журнал dpkg, связанный с текущей операцией. Пакет, добавленный
администратором между запусками, не становится собственностью установщика.
Перед удалением выполняется проверка плана APT:
он не должен затрагивать ранее существовавшие пакеты. Общий `autoremove` не
используется. Изменённые вручную файлы, параметры и обновлённые пакеты вызывают
отказ с указанием конфликта. Старые пакеты и чужие правила не перезаписываются.

Перед каждым вызовом dpkg через APT отдельная проверка запрещает замену уже
установленного пакета, включая обновление зависимости, понижение версии,
переустановку и смену архитектуры. Если новые компоненты требуют такого
изменения, установка остановится. Глобальные настройки APT не меняются.
Отметки manual/auto ранее существовавших пакетов при удалении не переписываются.

Прерванное отключение не считается успешным: отдельная запись о завершении
создаётся только после восстановления. Повторный запуск продолжает незавершённое
отключение. Задержавшийся таймер восстановления проверяет номер своей операции
и не останавливает новую настройку сети.

Если установленное нами ядро работает сейчас или выбрано в GRUB, удаление
сначала потребует загрузки сохранённого прежнего ядра. Пакет работающего ядра
не удаляется. После возврата и проверки сервера можно повторить удаление.
Если всё удалено, но livepatch остаётся в памяти, выводится отдельное требование
перезагрузки — это не объявляется полностью очищенным состоянием ядра.

Журнал, резервные копии и скачанный комплект сохраняются для восстановления;
они не запускают фильтрацию. Путь журнала: `/var/lib/ds-guard-safe/lifecycle/`.
После завершённого удаления следующая установка архивирует этот журнал и
создаёт новый цикл. Логи могут содержать системные сведения; публиковать их
без проверки нельзя.

Старые установки без исходного журнала автоматически не принимаются за новую:
восстановить неизвестные прежние параметры достоверно невозможно. Для них
нужен отдельный перенос проверенных резервных копий, а не подстановка
предполагаемых настроек по умолчанию.

Журналы прежнего кандидата без доказанного происхождения пакетов автоматически
не преобразуются. Для них требуется отдельная проверка. Пока установщик работает,
не редактируйте параллельно те же управляемые файлы: полного журнала происхождения
конкурентных внешних записей в файлы ещё нет. Дрейф между запусками отклоняется
до начала новой операции. Это ограничение кандидата; production-приёмка не завершена.

Коды: 0 — выбранное действие завершено; 20 — нужен отдельный шаг загрузки;
75 — операция занята; 78 — отказ из-за совместимости, конфликта или состояния;
остальные ненулевые коды — ошибка. При частичном выполнении полного режима
интерфейс отдельно сообщает, какой компонент уже установлен.
