# ds-guard-xanmod

Проверяемый установщик DoubleServers ds-guard 1.7.11 с исправленным nDPI,
готовыми модулями и сборками XanMod с LIVEPATCH. Релиз `v1.7.11-dsg1`.

## Установка одной командой

Выполнить **от root** на поддерживаемой системе:

```bash
bash -c 'set -e; f=$(mktemp); trap "rm -f -- \"$f\"" EXIT; curl --proto "=https" --tlsv1.2 -fsSL --connect-timeout 15 --max-time 60 https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/v1.7.11-dsg1/bootstrap.sh -o "$f"; bash "$f"'
```

Сначала полностью скачивается загрузчик. Он скачивает архив фиксированного
релиза, проверяет закреплённый SHA-256 и безопасно распаковывает его. Основной
установщик проверяет контрольные суммы всех файлов и совместимость системы.
GitHub-аккаунт или токен не нужны. Повторный запуск поддерживается.

Для проверки без установки передать `--check` последнему `bash "$f"`.
Для дополнительной проверки приложения передать
`--health-command 'команда, возвращающая 0 при исправной работе'`.
Общая проверка установщика не заменяет реальное клиентское подключение к VPN.

## Проверенные сочетания

| ОС amd64 | Точное ядро | Проверка |
|---|---|---|
| Ubuntu 22.04 | `6.8.0-87-generic` | Рабочий сервер, точные headers/GCC 12, повторная установка и загрузка |
| Ubuntu 24.04 | `6.8.0-147-generic` | Изолированная VM: трафик, отказ, откат, повторная установка и загрузка |
| Ubuntu 24.04 | `7.0.12-x64v2-dsg1-xanmod1` | Два рабочих сервера и VM |
| Ubuntu 24.04 | `7.2.9-x64v3-dsg1-xanmod1` | Два рабочих сервера и VM |

Другие ядра, ревизии и ОС отклоняются до установки. Это не поддержка всех
существующих ядер. После смены ядра требуется новая проверка совместимости.
Автоматическая сборка DKMS для неизвестных ядер отключена.

## Ограничения и защита от неудачной установки

- Обычная установка не заменяет ядро, не меняет его выбор в GRUB и не перезагружает сервер.
- Нужны systemd, amd64, собственное ядро, 4 ГиБ свободного диска и 1,5 ГиБ доступной RAM.
- Проверяются LIVEPATCH, политика подписи/lockdown, состояние пакетов и однозначный WAN.
- Чужая конфигурация Suricata и ds-guard 2.x не перезаписываются.
- Работа ограничена ресурсами и временем через systemd: до двух CPU, до 3 ГиБ RAM, без swap для установщика.
- При ошибке восстанавливаются только файлы и правила ds-guard. Полный firewall не сбрасывается.
- Модуль livepatch не выгружается принудительно. Проверяется идентичность файла и фактически загруженного модуля.
- Проверяются три слоя защиты, NFQUEUE, новые ошибки ядра, чужие правила firewall, маршруты, TCP-слушатели и HTTPS.

Коды завершения: `0` — локальная приёмка пройдена; `20` — новый модуль подготовлен,
нужна запланированная перезагрузка и повторный запуск; `78` — несовместимая система;
`75` — другая установка/восстановление; прочие ненулевые — ошибка.
Код `20` не означает, что новый модуль уже работает.

Журнал: `journalctl -u ds-guard-safe-install`. Резервные копии и результаты:
`/var/lib/ds-guard-safe/transactions/`, доступны root. Новые пакеты и каталоги
исходников могут оставаться после автоматического отката. Откат завершённой
установки, ядра или загруженного livepatch требует отдельного плана оператора;
автоматическое восстановление предназначено для незавершённой транзакции.

Фильтрация исходного ds-guard относится к **IPv4**. Непрерывная работа без сбоев,
совместимость с неизвестными ядрами и производительность на пиковом трафике
этими проверками не доказаны. Подробные результаты и сохранённые ограничения —
в [VALIDATION.md](VALIDATION.md).

## Если штатный XanMod собран без LIVEPATCH

Один модуль не добавит отсутствующую возможность ядра. В Release приложены
отдельные image/headers для двух проверенных XanMod, а также полные исходники.
Подготовка выполняется рядом со старым ядром; `linux-libc-dev` не устанавливается.

После распаковки проверенного release-архива и скачивания соответствующих двух
`.deb` из того же релиза подготовка имеет вид:

```bash
bash kernel-stage.sh 7.2.9-x64v3-dsg1-xanmod1 /каталог/с/двумя/deb
```

Для ветки 7.0 используется `7.0.12-x64v2-dsg1-xanmod1`. Скрипт проверяет SHA-256
из `kernels.json`, возможности CPU, драйверы, initramfs и запас места. Требуются
уже настроенные `GRUB_DEFAULT=saved` и сохранённая запись рабочего ядра.
Чужие DKMS-драйверы требуют отдельной проверки. Скрипт **только подготавливает**
ядро: выбор загрузки, консоль восстановления, перезагрузка и приёмка остаются
отдельными действиями оператора. На некоторых RAID GRUB не может сам очистить
одноразовый выбор; нельзя считать `grub-reboot` безусловной гарантией возврата.

Старые ядра следует сохранять до приёмки. Закреплённые сборки требуют отдельного
проверенного обновления для последующих исправлений безопасности; этот проект
не включает автоматическое обновление ядра.

## Исходники и воспроизведение

Основа: DoubleServers ds-guard 1.7.11,
[vel21ripn/nDPI](https://github.com/vel21ripn/nDPI/tree/63880be7697149ce954c91346bbd7b8cb8ea34d0)
и [XanMod Linux](https://gitlab.com/xanmod/linux).
Версии/commits: `UPSTREAM.json`; точные изменения: `ndpi-safety.patch`,
`source-edits.json`, `source-hashes.json`. `patch_sources.py` отклоняет неизвестные исходники.

Исправлены гибкие массивы, границы форматирования имени хоста, объявления для
Clang, неопределённые значения диагностики и совместимость с Linux 7.2, включая
актуальную логику освобождения GRE conntrack. UBSAN, проверки подписи и lockdown
не отключаются.

`reproduce-kernel.sh` и две исходные конфигурации описывают сборку на отдельной
Ubuntu 24.04 с LLVM 21.1.8. Побайтовое совпадение при другой дате/ключе сборки не
обещается. На production ядро не компилируется. Полные исходные архивы и их
контрольные суммы приложены к Release. Адресов серверов, ключей, паролей и
production-конфигураций в публикуемом комплекте нет.

Проверки разработки: `python3 -m unittest discover -p 'test_*.py'`.
Дополнительно: `test_hostname_bounds.py /путь/к/исправленному/ndpi` и
`test_compat72_copy.py` запускают проверки фактического кода с санитайзерами.
