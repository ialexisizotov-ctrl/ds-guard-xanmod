# ds-guard: интерактивная установка

Предварительный мастер **1.0.0-rc5** использует комплект
**v1.7.11-dsg2-rc5**. Для Ubuntu 22.04/24.04 на amd64 доступны точные
ядра и модули из каталога выпуска. Произвольное новое ядро совместимым
не считается; без подходящей проверенной сборки установка останавливается.

В SSH-консоли под root:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | bash
```

При запуске через sudo сохраните адрес текущего SSH-сеанса:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | sudo --preserve-env=SSH_CONNECTION bash
```

Русское меню предлагает полную установку, только ядро, ds-guard, сетевой
профиль, проверку, состояние, отключение, удаление и отмену управляемого
обновления. После переподключения запускается та же команда. Файлы
проверяются по закреплённым SHA-256 до исполнения. Без терминала установка
и перезагрузка автоматически не выбираются; для автоматизированной работы
нужно явно передать режим, например `bash -s -- --mode full`.

## Исправление продолжения после смены ядра

После успешной загрузки другого ядра могут измениться исходные значения
сетевых параметров. Прежняя проверка ошибочно останавливала первую
установку на `net.core.wmem_max` и других таких значениях.

Теперь перед первой записью защиты или сетевого профиля сохраняется отдельный
измеренный снимок новой загрузки. Исходный журнал прежнего ядра не
переписывается. Это измеренное состояние перед изменениями, а не
предположение об универсальных заводских настройках ядра.

Перенос разрешён только для свежей установки, ранее выполнившей подготовку
проверенного ядра: проверяются состояние пробной загрузки, файлы, владельцы,
пакеты и правила. Прежняя установка защиты, незавершённая операция,
постороннее изменение файлов или повторное стороннее изменение параметров
не становятся разрешёнными из-за одной перезагрузки.

Ядра, модули и сигнатуры относительно rc4 не менялись.
Сетевой профиль сохраняет исходные значения и не уменьшает существующие
лимиты буферов, очередей и conntrack; имеет отдельный механизм восстановления
непринятой настройки. Он не заменяет маршруты и посторонние правила firewall.

## Загрузка и возврат

Перед установкой другого ядра мастер сохраняет настройки GRUB, проверяет
образ и initramfs работающего ядра и закрепляет его как резервное.
Для обычного `GRUB_DEFAULT=0` используется отдельный управляемый файл,
исходный `/etc/default/grub` не переписывается. После подготовки нового
ядра предлагается отдельный выбор пробной перезагрузки.

Новое ядро сначала выбирается на одну загрузку. После повторного запуска
мастер продолжает установку, затем предлагает закрепление основного ядра.
Сначала проверьте SSH и реальную работу приложения. Старое ядро сохраняется.
Пустые одноразовые значения GRUB не считаются посторонним изменением;
проверка остальных метаданных и принадлежности файлов сохраняется.

Если Linux загрузился, но проверяемые сеть или SSH не работают, защитная
служба может запросить один возвратный перезапуск. При зависании до systemd
нужен независимый watchdog либо сброс через панель хостера. Безусловный
автоматический возврат после любого зависания не обещается.

Отключение и удаление учитывают собственные изменения по журналу.
Работающее или выбранное для загрузки ядро автоматически не удаляется:
сначала требуется отдельная загрузка сохранённого прежнего ядра.
Резервные копии и журналы сохраняются; сторонние изменения не перезаписываются.

## Комплект и контрольные суммы

[Выпуск v1.7.11-dsg2-rc5](https://github.com/ialexisizotov-ctrl/ds-guard-xanmod/releases/tag/v1.7.11-dsg2-rc5)
содержит `ds-guard-safe-v1.7.11-dsg2-rc5.tar.gz`:

- Архив SHA-256: `8970d7396d7db2d1683431e6f199739bb65dfe39240bfceee5c5941366221ea2`.
- Manifest внутри архива: `ecb74540d41119fd53f10047115a2128802c931fd7e316b997acf3d85c6a6d2c`.
- 83 файла полезной нагрузки плюс manifest; 60 993 299 байт архива.

Архив содержит собственный `SHA256SUMS`. Корневой `SHA256SUMS` репозитория
описывает опубликованные исходные файлы, а `WIZARD_SHA256SUMS` — файлы
мастера. Это разные manifest; корневой список не подменяет проверку архива.
Ранее опубликованные архивы не переписываются.

Основной установщик получает недостающие зависимости из отдельных
подписанных индексов Ubuntu, проверяет план без замены прежних пакетов и
учитывает подтверждённое происхождение собственных пакетов. Общий upgrade
ОС не выполняется. При незавершённой установке Suricata защитный запрет
не снимается без подтверждённой конфигурации и восстановления.

## Проверки и границы

Комплект rc5: **260 локальных тестов**; мастер: **180 тестов**.
Проверены синтаксис, контрольные суммы, фактическая распаковка и отрицательные
сценарии переноса исходного состояния. Результаты в `RC5_VALIDATION.json`.
Старые документы и квитанции rc4 внутри архива сохранены как история;
они не являются текущими контрольными суммами rc5.

На одном дополнительном сервере Ubuntu 24.04 после пользовательской
перезагрузки в проверенный XanMod прошли полная установка и повтор
публичной команды. nDPI и Suricata пропустили контрольные пакеты и
заблокировали по три тестовые сигнатуры. Прямой VLESS-клиент прошёл
5/5 проверок до публичного повтора и 5/5 после: внешний IP, HTTPS,
скачивание, отправка данных и UDP DNS. Сохранность прежних пакетов,
контрольных файлов, VPN-процесса и посторонних правил проверена.

Это не приёмка всей инфраструктуры, публичной подписки, мобильных клиентов,
пиковой или непрерывной нагрузки. Следующая перезагрузка уже с установленным
guard в этой приёмке не выполнялась. Выпуск остаётся предварительным.

Подробности режимов: [интерактивный мастер](INTERACTIVE_RU.md).
Стабильный `bootstrap.sh` остаётся отключённым.
