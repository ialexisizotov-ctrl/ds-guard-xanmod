# ds-guard-xanmod

**Готового принятого релиза сейчас нет. `v1.7.11-dsg1` отозван.**
Длительное наблюдение после короткой приёмки обнаружило чтение за пределами
буфера в `realloc_wrapper` nDPI при обработке TLS. Старый установочный архив
переименован, загрузчик в `main` отключён. Не устанавливайте отозванную сборку.

В `main` готовится исправление. Оно использует штатный `krealloc` для памяти
kmalloc, сохраняет фактическую запрошенную длину vmalloc-выделений и проверяет
переполнение размера calloc. Исправление не отключает проверки памяти ядра.
Подробные текущие результаты: [VALIDATION.md](VALIDATION.md).

## Назначение

Проверяемый установщик DoubleServers ds-guard 1.7.11 с исправлениями nDPI,
готовыми модулями под точные ядра и отдельными сборками XanMod с LIVEPATCH.
После полной приёмки будет опубликован новый закреплённый релиз для установки
одной командой. Аккаунт GitHub для скачивания публичного релиза не нужен.

## Границы совместимости

Сборки подготовлены для Ubuntu amd64:

| ОС | Точное ядро |
|---|---|
| Ubuntu 22.04 | `6.8.0-87-generic` |
| Ubuntu 24.04 | `6.8.0-147-generic` |
| Ubuntu 24.04 | `7.0.12-x64v2-dsg1-xanmod1` |
| Ubuntu 24.04 | `7.2.9-x64v3-dsg1-xanmod1` |

Сборка не равна приёмке в эксплуатации. Неизвестные ядра и сочетания ОС
отклоняются до установки. Совместимость со всеми существующими ядрами не
заявляется. Автоматическая сборка DKMS для неизвестных ядер отключена.

Штатный XanMod без `CONFIG_LIVEPATCH` нельзя исправить одним модулем.
Отдельная подготовка image/headers сохраняет старое ядро; выбор загрузки,
план возврата и перезагрузка требуют отдельной проверки оператора. На RAID
одноразовый выбор GRUB не всегда автоматически очищается. Закреплённым ядрам
необходимы последующие проверенные обновления безопасности.

## Защита production

- Обычная установка не заменяет ядро, не выбирает запись GRUB и не перезагружает сервер.
- Проверяются архитектура, точная ОС/ядро, LIVEPATCH, подпись/lockdown, пакеты,
  дисковое пространство, память и однозначный WAN.
- Ошибки ядра во всей текущей загрузке останавливают активацию, даже если они
  появились до запуска установщика.
- Чужая конфигурация Suricata и ds-guard 2.x не перезаписывается.
- systemd ограничивает установку двумя CPU, памятью и временем.
- Откат незавершённой транзакции затрагивает только файлы и правила ds-guard.
  Полный firewall не сбрасывается.
- Livepatch-модуль не выгружается принудительно. Сравниваются ELF build-id
  файла и фактически загруженного модуля.
- Проверяются три слоя фильтрации, NFQUEUE, ошибки ядра, чужие правила,
  маршруты, TCP-слушатели и HTTPS. Нужна дополнительная проверка реального
  клиентского пути приложения.

Код `20` означает только подготовку нового модуля: нужна запланированная
перезагрузка и повторная приёмка. Он не подтверждает работу нового модуля.
Код `78` означает отказ по совместимости или состоянию системы.

Журналы: `journalctl -u ds-guard-safe-install`; транзакции и резервные копии:
`/var/lib/ds-guard-safe/transactions/`, доступны root. Новые пакеты и исходники
могут оставаться после отката. Возврат уже принятой установки, ядра или
загруженного livepatch выполняется по отдельному плану.

Исходный ds-guard фильтрует IPv4. Эти проверки не доказывают фильтрацию IPv6,
пиковую производительность или непрерывную работу без сбоев.

## Исходники и проверки

Основа: DoubleServers ds-guard 1.7.11,
[vel21ripn/nDPI](https://github.com/vel21ripn/nDPI/tree/63880be7697149ce954c91346bbd7b8cb8ea34d0)
и [XanMod Linux](https://gitlab.com/xanmod/linux).
Версии — `UPSTREAM.json`; изменения — `ndpi-safety.patch`, `source-edits.json`
и `source-hashes.json`. Неизвестные исходники отвергаются, дерево DKMS новой
версии создаётся отдельно от старой. Production-адреса и учётные данные в
публичный комплект не включаются.

```bash
python3 -m unittest discover -p 'test_*.py'
python3 test_allocator.py /путь/к/исправленному/ndpi
python3 test_hostname_bounds.py /путь/к/исправленному/ndpi
python3 test_compat72_copy.py
```

Проверка allocator использует фактический исправленный код. Старый код должен
воспроизвести ошибку под ASan; исправленный — пройти проверки роста, уменьшения,
отказов выделения и освобождения метаданных под ASan/UBSan. Для этих проверок
нужен Clang 21 на отдельной машине сборки.

История короткой приёмки отозванного релиза сохранена в
[HISTORICAL_DSG1_VALIDATION.md](HISTORICAL_DSG1_VALIDATION.md).
