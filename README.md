# ds-guard: интерактивная установка

Предварительный комплект **v1.7.11-dsg2-rc4**, мастер **1.0.0-rc2**.
Для Ubuntu 22.04/24.04 на amd64 используются только точные ядра и модули
из каталога выпуска. Произвольное новое ядро автоматически совместимым не считается.

В SSH-консоли под root:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | bash
```

При запуске через sudo нужно сохранить адрес текущего SSH-сеанса:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | sudo --preserve-env=SSH_CONNECTION bash
```

Мастер предлагает русский выбор: полная установка, только XanMod, только Ubuntu,
ds-guard, сеть, проверка, состояние, отключение, удаление и отмена обновления
прежней установки. После переподключения запускается та же команда.
Перед исполнением файлы мастера и комплект проверяются по закреплённым SHA-256.

## Изменения rc4

- Недостающие зависимости получают отдельные подписанные индексы официального
  архива Ubuntu для текущей поддерживаемой версии ОС. Источники и списки пакетов
  сторонних репозиториев не переписываются и не отключаются.
- Перед установкой проверяется план APT. Если он требует замены прежних пакетов,
  допускается одна попытка подобрать отсутствующие зависимости с той же исходной
  версией, что у уже установленной группы пакетов. Выбор учитывает политику APT;
  повторный план должен сохранять все прежние пакеты, иначе установка остановится.
- Для первой установки Suricata предусмотрена защита от запуска пакетной службы
  до готовности конфигурации установщика.
- Пункты «Состояние» и «Проверка» завершают просмотр напрямую. Код 20, который
  сообщает о ранее подготовленном ядре, не трактуется как новая подготовка
  загрузки и не добавляет указание перезагрузить сервер.
- При повторном запуске независимые обновления системных пакетов не считаются
  изменениями установщика. Принадлежность пакетов определяется подтверждениями
  собственных операций; изменение версии принадлежащего установщику пакета
  по-прежнему останавливает продолжение.

Помощник GRUB `boot_trial.py`, двоичные модули и каталог проверенных ядер
сохранены относительно предыдущего выпуска. Существующие архивы и результаты
прошлых проверок не заменялись.

Если пакетная установка завершилась частично и YAML-конфигурация появилась
без исходной резервной копии, защитный запрет запуска сохраняется.
Такой возврат считается незавершённым и требует диагностики.

## Смена ядра и возврат

Новое ядро устанавливается рядом с прежним и выбирается для одной пробной
загрузки. Перезагрузка требует отдельного выбора в меню; безопасный вариант
по умолчанию — продолжить позже. После подключения мастер продолжит сохранённый
режим. Закрепление нового ядра также требует явного выбора после проверки.

При доступном systemd защитная служба проверяет SSH, адрес и маршрут и может
запросить один возвратный перезапуск. Если ядро зависло до systemd, для сброса
нужны независимый watchdog или панель хостера. Сам скрипт не обеспечивает
безусловное восстановление после любого зависания.

После возврата мастер предлагает посмотреть состояние, закрыть попытку или
выйти. Новая проба автоматически не повторяется. При неоднозначном журнале
или изменении чужих настроек действие останавливается.

Подробности: [интерактивный мастер](INTERACTIVE_RU.md),
[эксплуатация и восстановление](OPERATIONS_RU.md).

## Проверки и ограничения

Текущая локальная проверка: **256 тестов основного комплекта**
и **136 тестов мастера и boot helper**. Архив проверяется повторно,
включая распаковку созданным мастером и все контрольные суммы.

Отдельная проверка защиты использовала настоящий systemd и временную тестовую
службу; `suricata -T` был заменён имитацией. Перезагрузка всей машины и потеря
питания не проверялись. Пакет Suricata из подписанного официального индекса
только скачан и исследован, без установки.

**На момент фиксации комплекта production-приёмка ещё не завершена.**
Последующие результаты см. в описании релиза.
Первая попытка rc4 безопасно остановилась до изменения пакетов через dpkg:
план зависимостей требовал обновления уже установленной библиотеки libevent.
Тот комплект и результаты сохранены отдельно; исправленный подбор зависимостей
в следующем комплекте позволил завершить полную установку. Его повторный запуск
затем безопасно отказал, ошибочно приписав установщику независимые обновления
системных пакетов. Текущий комплект исправляет эту проверку принадлежности;
его повторная production-проверка на момент фиксации ещё не выполнена.
Проверка существующего прямого узла до установки не подтверждает работу этого
выпуска, всей публичной подписки или всех серверов. Приёмка реального
клиентского трафика выполняется отдельно после установки.

Проверки предыдущих rc3/мастера rc1 не выдаются за новые проверки rc4.
Точный объём: [VALIDATION.md](VALIDATION.md), `RC4_VALIDATION.json` и
`WIZARD_VALIDATION.json`. Стабильный `bootstrap.sh` остаётся отключённым.

Для старой vendor-установки без исходного снимка возврат означает состояние
перед управляемым обновлением. Полностью восстановить неизвестное состояние
до первоначального стороннего установщика автоматически нельзя.
