# ds-guard-xanmod

Единый установщик ds-guard для Ubuntu 22.04/24.04 с проверкой совместимости ядра,
исправленным nDPI и отдельными сборками XanMod.

**Статус: разработка и испытания. Готовый production-релиз ещё не опубликован.**
Не запускайте текущую ветку на рабочем сервере до появления принятого релиза.

Установщик проверяет ядро до изменений. Обычный запуск не меняет ядро и не
перезагружает сервер. Несовместимость, недостаток ресурсов, чужая установка
Suricata или ds-guard 2.x останавливают работу. Неизвестное ядро не считается
совместимым только потому, что модуль компилируется.

Сборка ограничивается отдельной группой ресурсов systemd. Сохраняются только
затрагиваемые файлы и правила. Откат не восстанавливает весь firewall и не
выгружает принудительно работающий livepatch-модуль. Обновление уже загруженного
модуля возвращает отдельный статус `20 / REBOOT_REQUIRED`; это не успешная
проверка новой защиты. Несовместимая система возвращает `78`, ошибка — `1`.

Проверяются точные сочетания ОС и ядра: Ubuntu 22.04 / 6.8.0-87-generic;
Ubuntu 24.04 / 6.8.0-147-generic, 7.0.12-x64v2-dsg1-xanmod1 и
7.2.9-x64v3-dsg1-xanmod1. Другие ревизии, Debian и другие дистрибутивы
пока отклоняются до изменений. После обновления ядра нужна отдельная проверка
совместимости; автоматическая сборка DKMS для неизвестного ядра отключена.

Исправления: корректный гибкий массив nDPI, проверка поддержки GCC-флага для
Clang, сохранение актуальной логики уничтожения GRE conntrack в Linux 7.2.
Дополнительно исправлены остальные хвостовые массивы нулевой длины,
инициализация и границы буфера имени хоста, объявления функций для Clang
и неинициализированные значения в диагностике времени. Проверка фактической
функции имени хоста прошла 768 случаев под ASan/UBSan.
Для штатного XanMod без `CONFIG_LIVEPATCH` требуется совместимая сборка ядра.
Принудительная загрузка, отключение проверки подписей, UBSAN или lockdown
не используются.

Область фильтрации исходного ds-guard — IPv4. Локальная проверка установщика
не заменяет проверку конкретного VPN/приложения; для неё предусмотрен
`--health-command`. Исходные версии и контрольные суммы находятся в
`UPSTREAM.json` и `source-hashes.json`. Все production-данные исключены.

Основа: DoubleServers ds-guard 1.7.11 и
[vel21ripn/nDPI](https://github.com/vel21ripn/nDPI/tree/63880be7697149ce954c91346bbd7b8cb8ea34d0).
Исходники ядер: [XanMod Linux](https://gitlab.com/xanmod/linux).

Проверки разработки: `python3 -m unittest discover -p 'test_*.py'`.

`reproduce-kernel.sh` и две исходные конфигурации описывают сборку ядра на
отдельной машине Ubuntu 24.04 с официальным LLVM 21.1.8. Скрипт проверяет commit
XanMod и включает LIVEPATCH, сохраняя остальные настройки. Это процедура
пересборки; одинаковый побайтовый результат при другой дате и ключе сборки
не обещается. На production ядро не компилируется.

Изменения nDPI доступны в `ndpi-safety.patch`, точные исходные и итоговые хеши —
в `source-hashes.json`. Скрипт `patch_sources.py` отказывается менять неизвестные
исходники. `test_hostname_bounds.py /path/to/patched/ndpi` проверяет фактический
код форматирования имени хоста с санитайзерами.
