# ds-guard: установка одной командой

Предварительный выпуск **v1.7.11-dsg2-rc9**, мастер **1.0.0-rc11**.
В SSH-консоли под root:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | bash
```

Для sudo используйте `sudo --preserve-env=SSH_CONNECTION bash` вместо `bash`.
Мастер показывает действия, состояние и причины остановки по-русски. Файлы
мастера и архив проверяются по закреплённым SHA-256 перед исполнением.

## Сохранение существующего ядра

Пункт **11. ds-guard и сетевые параметры на текущем ядре, без смены ядра**
устанавливает защиту и сетевой профиль без установки другого ядра, изменения
GRUB и перезагрузки. Для автоматизированного запуска этого режима:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | bash -s -- --mode full --kernel-policy keep
```

Если при выборе полной установки безопасная пробная загрузка невозможна
(например, `/boot` на RAID/LVM) либо подходящего нового ядра нет в каталоге,
мастер проверит текущее ядро и предложит продолжить на нём. Решение принимает
оператор. Без терминала политика сама не меняется: нужно явно указать `keep`.
Другие ошибки загрузчика и незавершённые изменения не обходятся этим выбором.

В rc6 добавлен точный модуль для **Ubuntu 24.04 / 7.0.0-34-generic**.
Это поддержка уже работающего ядра; оно не добавлено в каталог автоматической
смены ядер. Поддержка соседних версий, например `7.0.0-38-generic`, из неё
не следует. Для неизвестного ядра установка остановится до загрузки модуля.

Остальные точные ABI сохранены: `6.8.0-87-generic` для Ubuntu 22.04;
`6.8.0-147-generic`, `7.0.12-x64v2-dsg1-xanmod1` и
`7.2.9-x64v3-dsg1-xanmod1` для Ubuntu 24.04. Архитектура — amd64.
Принудительная загрузка несовместимого модуля не используется.

## Другие режимы

В меню доступны полная установка, только XanMod, только Ubuntu, только
ds-guard, только сеть, проверка без установки, состояние, отключение,
удаление и отмена обновления прежней установки.

Новое ядро устанавливается рядом с прежним. Перезагрузка и постоянное
закрепление нового ядра — отдельные действия. После переподключения запускается
та же команда. При зависании до systemd нужен независимый сброс у хостера:
скрипт внутри остановившейся ОС не может гарантировать возврат.

Сохранение текущего ядра не меняет уже существующий выбор следующей загрузки.
Если системное обновление ранее установило другое ядро, проверьте его
совместимость перед плановой перезагрузкой.

## Проверки

Основной комплект — 275 тестов, мастер — 203. На отдельной VM с точным
`7.0.0-34-generic` проверяются установка без смены ядра, повторный запуск,
фильтрация DNS/nDPI/Suricata и 600 TLS-соединений с контролем ошибок ядра.
Точные результаты и границы приведены в [VALIDATION.md](VALIDATION.md);
последующая серверная приёмка — в описании релиза.

Произвольные ядра, все production-серверы, мобильные клиенты и пиковая
нагрузка этим не объявляются проверенными. Предыдущие архивы и результаты
сохраняются; стабильный `bootstrap.sh` пока отключён.

Подробности: [интерактивный мастер](INTERACTIVE_RU.md),
[эксплуатация и восстановление](OPERATIONS_RU.md).

## Исправление rc7

Проверка фильтра ждёт завершения обновления правил под той же блокировкой.
Неполная промежуточная генерация больше не вызывает ложный откат.
Ошибка уже завершённого фильтра по-прежнему останавливает установку.
Ядра, модули, сетевой профиль и загрузчик в этом выпуске не изменены.

## Повтор после отката в rc8

Стандартная конфигурация Suricata, оставленная прежним откатом ds-guard,
распознаётся по защищённому журналу первичной установки и точному совпадению файла.
Принятие возможно только после завершённого отката, с отключённой службой без чужих drop-in.
Изменённые и посторонние настройки не заменяются.

## Отложенная пробная загрузка: мастер 1.0.0-rc11

Выбор «Отложить» не назначает новое ядро в GRUB. Обычная команда `reboot`
после отсрочки запускает прежнее ядро. Повтор той же команды установщика теперь
снова предлагает продолжить подготовленную загрузку или отменить её.
Пакеты повторно не устанавливаются, автоматического перезапуска нет.

После явного выбора перезагрузки повторно проверяются сохранённые файлы,
GRUB, образы обоих ядер и действующие SSH/сеть. Только затем обновляется
идентификатор исходной загрузки и назначается одноразовый выбор нового ядра.
Неудачная уже назначенная попытка, постороннее ядро и изменённые настройки
не принимаются за отсрочку. Для них сохраняется отдельное восстановление.

Основной комплект rc8, ядра, модули и сетевой профиль не изменены. Проверки
мастера: 203 автоматических теста. Они не заменяют фактическую загрузку сервера.

## Обязательные зависимости: комплект rc9

APT устанавливает только запрошенные компоненты и обязательные зависимости.
Необязательные Recommends/Suggests не добавляются: например, дополнительные
обновляющие утилиты Suricata могли требовать замены уже установленного Perl.
Собственные правила ds-guard поставляются установщиком и работают без этих утилит.
Проверка запрета удаления/замены прежних пакетов, их hold/pin и проверка подписей
сохранены. Общие настройки APT сервера не меняются. На проверенном сервере
симуляция подтвердила 33 новых пакета и ноль изменений прежних пакетов.

Мастер rc11 включает исправление отложенной загрузки rc10. Ядра, двоичные модули
и сетевой профиль не изменены. 275 тестов основного комплекта и 203 теста мастера.
Все серверы, произвольные ABI и непрерывная работа этим не объявляются проверенными.
