# ds-guard-xanmod

**v1.7.11-dsg2-rc3 — кандидат предварительного выпуска. Лабораторная приёмка завершена; production-приёмка не выполнена.**

rc3 добавляет перенос строго известной установки ds-guard 1.7.11, в которой
nDPI уже приостановлен защитными файлами. Исправленный модуль сначала
подготавливается для работающего ядра; при необходимости загрузить его
перезагрузка выполняется отдельно. Для отмены такого переноса предусмотрен
`rollback-upgrade`.

Текущий код — freeze-v6: 200 локальных тестов прошли без ошибок и пропусков.
Завершённые VM-сценарии v4 и лабораторное завершение журнала v5 сохранены
с отдельным указанием версии. Повторный full v5 остановился с кодом 78 на
штатной смене банка правил A/B. Пять команд и шесть проверок исправленного
v6 прошли. Финальное чтение подтвердило исходники и установленный код;
VM штатно выключена, базовый образ сохранён без изменений.

Тесты bootstrap проверили передачу аргументов, отказ при неверном SHA256,
ошибке загрузки, выходе пути за пределы архива и символической ссылке.
Сеть и настоящий установщик в этих пяти тестах не запускались. VM-результаты
относятся к ограниченному по времени изолированному стенду. Они и локальные
тесты не подтверждают работоспособность production-серверов. Legacy-стенд
использовал исправленный rc2-модуль с изменённым только ELF build-id для
моделирования старой идентичности, а не опасный прежний бинарник vendor.
Точный объём проверок перечислен в `REVIEW3_VALIDATION.json`.

Первая попытка повторного `full` завершилась кодом `1` за 398 секунд:
проверка приложения получила `curl 28` при строгом HTTPS к Google
(тайм-аут 20 секунд, 0 полученных байт). Транзакция продукта откатилась.
Это сохранённая неудачная попытка, а не PASS; причина сетевого тайм-аута
пока не установлена. Следующие сценарии автоматически после неё не запускались.
Отдельные проверки состояния и HTTPS прошли; один точный повтор `full`
завершился успешно и хранится отдельным результатом. Текущие результаты v6 приведены отдельно выше. Указанное время измерено на QEMU TCG и
не является оценкой длительности на production.

В следующем новом цикле v4 финальный снимок APT столкнулся с ошибкой
переименования кэша во время APT Daily. Worker проверил три слоя, но общий
журнал не завершился; ранее напечатанное «ГОТОВО» оказалось преждевременным.
Freeze-v5 отключает запись APT-кэша в этих read-only снимках и переносит
финальный статус успеха после завершения журнала. Лабораторное восстановление
только доказанной операции v4 отдельным исходником v5 не объявляется
автоматическим восстановлением production.

Во второй лабораторной попытке журнал завершён штатно: исходный baseline
сохранён, pending снят, установленная библиотека осталась v4; файлы, правила,
службы, значения и пакеты не менялись. Причина первой остановки проверки
не доказана: исходного raw-сравнения нет, таймеру она не приписывается.
Принятая матрица v6 содержит пять команд и шесть проверяемых результатов:
один фактический откат после `tune` проверяет и возврат обновления, и возврат сети.

Freeze-v6 распознаёт только строго доказанную смену банка A/B с той же
политикой: исходные списки, порядок правил, места подключения, чужая политика,
права и содержимое файла поколения должны совпасть с проверяемым переходом.
Это не разрешение произвольной смены DNS-адресов или редактирования firewall.
Откат сохраняет исходный журнал и возвращает файл поколения из его точной
копии, даже если до и после установки он совпадал. На VM уже доказаны
условия проверки: before == after, текущее поколение отличается, строгая
проверка продукта принимает именно этот переход. Общий откат завершил
227/227 шагов и подтвердил возврат исходного поколения, файлов и 15 сетевых
значений. Livepatch остался в памяти; код 20 требует отдельной перезагрузки.

**Принятого стабильного релиза сейчас нет. `v1.7.11-dsg1` отозван.**
Длительное наблюдение после короткой приёмки обнаружило чтение за пределами
буфера в `realloc_wrapper` nDPI при обработке TLS. Старый установочный архив
переименован, стабильный загрузчик в `main` отключён. Не устанавливайте
отозванную сборку.

Исправление использует штатный `krealloc` для памяти kmalloc, сохраняет
фактическую запрошенную длину vmalloc-выделений и проверяет переполнение
размера calloc. Проверки памяти ядра остаются включёнными.
Подробные результаты: [VALIDATION.md](VALIDATION.md).
Русское меню и инструкции: [OPERATIONS_RU.md](OPERATIONS_RU.md).

## Установка одной командой

Команда для
[предварительного выпуска v1.7.11-dsg2-rc3](https://github.com/ialexisizotov-ctrl/ds-guard-xanmod/releases/tag/v1.7.11-dsg2-rc3).
Запускайте команду в Bash на целевом Linux-сервере:

```bash
( ds_tmp=$(mktemp -d) && trap 'rm -rf -- "$ds_tmp"' EXIT && curl --proto '=https' --proto-redir '=https' --tlsv1.2 -fsSL --connect-timeout 15 --max-time 120 https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/v1.7.11-dsg2-rc3/candidate.sh -o "$ds_tmp/candidate.sh" && sudo bash "$ds_tmp/candidate.sh" --mode full )
```

Команда скачивает отдельный `candidate.sh` из конкретного тега, затем запускает
его с правами root. Загрузчик проверяет закреплённый SHA256 архива этого
выпуска перед запуском установки. Временный файл удаляется при завершении;
интерактивная оболочка остаётся открытой. Для загрузки публичного выпуска
аккаунт GitHub не нужен. Код `20` означает, что требуется отдельная
запланированная перезагрузка; после неё повторите ту же команду.
Загрузчик стабильного канала в `main` остаётся отключённым.

## Назначение и режимы

Проверяемый установщик DoubleServers ds-guard 1.7.11 с исправлениями nDPI,
готовыми модулями под точные ядра и отдельными сборками XanMod с LIVEPATCH.
В распакованном комплекте с проверенным `SHA256SUMS` команда
`sudo bash setup.sh` открывает русское меню. Без терминала укажите `--mode`.

| Режим | Действие |
|---|---|
| `full` | Проверенное ядро, ds-guard и профиль сети |
| `kernel` | Только подготовка проверенного ядра |
| `tune` | Только профиль сети |
| `guard` | Только ds-guard для работающего ядра |
| `check` | Выбор версии и план без изменений |
| `status` | Службы, модуль, очереди, параметры и ошибки |
| `disable` | Отключение и возврат сетевых значений для новой установки с исходным журналом |
| `remove` | Удаление собственных изменений новой установки по исходному журналу |
| `rollback-upgrade` | Возврат к состоянию непосредственно перед переносом прежнего ds-guard |

`check` не заменяет полный контроль ресурсов, загрузчика и драйверов перед
изменением. `status` не проверяет клиентский VPN. `--health-command 'КОМАНДА'`
добавляет проверку приложения; она должна быть ограничена по времени и не
менять настройки системы. `--tuning keep` исключает профиль сети из полного режима.

## Границы совместимости

Сборки подготовлены для Ubuntu amd64:

| ОС | Точное ядро |
|---|---|
| Ubuntu 22.04 | `6.8.0-87-generic` |
| Ubuntu 24.04 | `6.8.0-147-generic` |
| Ubuntu 24.04 | `7.0.12-x64v2-dsg1-xanmod1` |
| Ubuntu 24.04 | `7.2.9-x64v3-dsg1-xanmod1` |

Сборка не равна приёмке в эксплуатации. Неизвестные ядра и сочетания ОС
отклоняются до установки. Автоматическая сборка DKMS для неизвестных ядер
отключена; совместимость со всеми существующими ядрами не заявляется.

`--kernel-policy prefer-xanmod` выбирает наибольшую проверенную версию XanMod,
совместимую с ОС и общим набором инструкций всех CPU; при отсутствии такого
комплекта выбирается проверенный Ubuntu. `xanmod` запрещает fallback,
`ubuntu` выбирает Ubuntu, `keep` сохраняет работающее ядро. Fallback не
понижает работающее ядро, включая номер ABI Ubuntu. Более свежий upstream
не становится проверенным автоматически; фонового обновления ядра нет.

Штатный XanMod без `CONFIG_LIVEPATCH` нельзя сделать совместимым заменой
одного модуля. Проверенные пакеты image/headers устанавливаются рядом с
прежними. Состав драйверов проверяется; в частности, загруженные
`vga16fb`/`vgastate` несовместимы с текущими XanMod-комплектами. Проверку
нельзя отключать ради перехода. Суффикс `dsg1` в именах ядер сохранён:
ядро не содержит nDPI; исправленный модуль имеет отдельную версию
`1.7.63880be7697-dsg2`.

Подготовка другого ядра заканчивается кодом 20: работающая система не
переключается, перезагрузка не запускается. Выбор загрузки, сохранённый
fallback GRUB, доступ к консоли и перезагрузка проверяются отдельно.
На RAID одноразовый выбор GRUB не всегда очищается автоматически.
Закреплённым ядрам необходимы последующие проверенные обновления безопасности.

## Перенос прежней установки 1.7.11

Поддерживается только известное состояние: точная версия 1.7.11, ожидаемые
защитные файлы приостановки nDPI, остановленные службы guard и отключённый
таймер. До первого шага проверяются работающая Suricata, очереди 0 и 1,
DNS/NFQUEUE-правила и отсутствие активных nDPI-правил. Неизвестная версия,
изменённый защитный файл и ds-guard 2.x отклоняются.

Перед изменениями сохраняются файлы, пакеты, параметры, службы, правила и
идентичность загруженного модуля. Прежние пакеты не становятся собственностью
нового установщика. В `full` сначала обновляется guard для работающего ядра;
смена ядра откладывается.

Если в памяти другой модуль, исправленная сборка записывается на диск без
принудительной выгрузки livepatch и без снятия защитной приостановки.
Результат — код 20. Выполните отдельную запланированную перезагрузку и затем
повторите ту же команду. Активация требует точной идентичности исправленного
модуля в памяти и на диске и чистого журнала ядра. Известная старая ошибка
allocator может допустить только подготовку на диске; запуск фильтрации
при ошибках ядра запрещён.

Сохранение временных DNS/NFQUEUE-правил через перезагрузку не обещается.
Продолжение распознаётся по журналу предыдущей операции; до повторного
применения и проверки трёх слоёв фильтрация после загрузки не считается
принятой. Добавленная защита незавершённой активации проверяет смену загрузки
и подтверждение точной транзакции. В ограниченной VM-проверке после настоящей
холодной загрузки она запретила запуск при уже снятом прежнем запрете;
активные nDPI-правила не появились. Этот результат не доказывает работу
при любой аппаратной аварии или на произвольной системе.

Проверенный запрет запуска после холодной загрузки не доказывает полное
восстановление после внезапного отключения питания. Для такой аварии ещё не
подтверждены полнота журналов и безопасное автоматическое продолжение;
неизбежный безопасный отказ тоже не гарантируется. Это ограничение
предварительного выпуска. Подробности — в [VALIDATION.md](VALIDATION.md).

`rollback-upgrade` возвращает сохранённое состояние непосредственно перед
обновлением — прежнюю установку с приостановленным nDPI. Это не удаление
всех изменений с момента первоначального запуска vendor-скрипта. Если для
возврата состава загруженных модулей нужна перезагрузка, это указывается
отдельно; livepatch не выгружается принудительно.

**Обычные `disable` и `remove` для перенесённой прежней установки пока не
поддерживаются и останавливаются до изменений.** Для новой установки с
полным исходным журналом эти режимы доступны по условиям
[OPERATIONS_RU.md](OPERATIONS_RU.md). Старые журналы без доказанного
происхождения пакетов автоматически не преобразуются.

## Защита системы и сеть

- Сам режим `guard` не заменяет ядро, не выбирает запись GRUB и не перезагружает сервер.
- Проверяются точная ОС/ядро, LIVEPATCH, подпись/lockdown, пакеты, ресурсы и однозначный WAN.
- Существующие зависимости не обновляются, не понижаются и не переустанавливаются скрыто при добавлении новых пакетов.
- Установка ограничена systemd по CPU, памяти и времени. Восстановление не должно работать одновременно с незавершённой группой рабочих процессов.
- Откат затрагивает собственные файлы и правила; полный firewall не сбрасывается. Задержавшийся таймер восстановления сети проверяет принадлежность операции.
- Проверяются три локальных слоя, NFQUEUE, ошибки ядра, чужие правила, маршруты, TCP-слушатели и HTTPS. Реальный клиентский путь проверяется дополнительно.

Профиль сети включает BBR, `fq` для новых интерфейсов, TCP Fast Open,
MTU probing, буферы TCP, очереди и conntrack с учётом памяти. Более высокие
действующие лимиты не уменьшаются. Общий `sysctl --system`, перезапуск сети
и замена действующих qdisc или ограничений скорости не выполняются.
Размер хеш-таблицы conntrack применяется при следующей отдельной загрузке
модуля. Настройки сами по себе не доказывают рост скорости.

Первоначальный журнал сохраняется между запусками. Конфликт с последующими
изменениями администратора вызывает отказ; параллельно редактировать
управляемые файлы во время установки нельзя. При удалении новой установки
проверяется план APT, ранее существовавшие пакеты и их manual/auto-отметки
сохраняются, общий `autoremove` не используется. Ядро, которое работает или
выбрано для следующей загрузки, не удаляется.

## Статусы и журналы

| Код | Значение |
|---|---|
| `0` | Выбранное действие завершено; объём проверки определяется режимом |
| `20` | Нужен отдельный шаг загрузки или перезагрузка для требуемого ядра/модуля; точная причина указана выбранным режимом |
| `75` | Операция занята |
| `78` | Отказ по совместимости, конфликту или состоянию системы |
| Другой ненулевой | Ошибка; проверьте журнал и результат восстановления |

Журнал установки: `journalctl -u ds-guard-safe-install`.
Транзакции и резервные копии: `/var/lib/ds-guard-safe/transactions/`.
Исходный журнал установки: `/var/lib/ds-guard-safe/lifecycle/`.
Эти данные доступны root и могут содержать системные сведения; перед
публикацией их необходимо проверить. Новые пакеты и исходники могут
оставаться после отката отдельного неудачного шага; это не объявляется
полным удалением установки.

Исходный ds-guard фильтрует IPv4. Эти проверки не доказывают фильтрацию IPv6,
пиковую производительность или непрерывную работу без сбоев. Статус
production-приёмки этого кандидата остаётся отрицательным до свежих
последовательных проверок серверов и реальных клиентских путей.

## Исходники и проверки

Основа: DoubleServers ds-guard 1.7.11,
[vel21ripn/nDPI](https://github.com/vel21ripn/nDPI/tree/63880be7697149ce954c91346bbd7b8cb8ea34d0)
и [XanMod Linux](https://gitlab.com/xanmod/linux).
Версии — `UPSTREAM.json`; изменения — `ndpi-safety.patch`, `source-edits.json`
и `source-hashes.json`. Неизвестные исходники отвергаются; дерево DKMS новой
версии создаётся отдельно от старой. Production-адреса и учётные данные
в публичный комплект не включаются.

```bash
python3 -m unittest discover -p 'test_*.py'
python3 test_allocator.py /путь/к/исправленному/ndpi
python3 test_hostname_bounds.py /путь/к/исправленному/ndpi
python3 test_compat72_copy.py
```

Проверка allocator использует фактический исправленный код. Старый код должен
воспроизвести ошибку под ASan; исправленный — пройти проверки роста,
уменьшения, отказов выделения и освобождения метаданных под ASan/UBSan.
Для этих проверок нужен Clang 21 на отдельной машине сборки.

История короткой приёмки отозванного релиза сохранена в
[HISTORICAL_DSG1_VALIDATION.md](HISTORICAL_DSG1_VALIDATION.md).
