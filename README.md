# ds-guard: интерактивная установка

Предварительный мастер **1.0.0-rc3** использует прежний проверенный комплект
**v1.7.11-dsg2-rc4**. Для Ubuntu 22.04/24.04 на amd64 доступны только точные
ядра и модули из каталога выпуска; произвольное новое ядро совместимым не считается.

В SSH-консоли под root:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | bash
```

При запуске через sudo сохраните адрес текущего SSH-сеанса:

```bash
curl -fsSL https://raw.githubusercontent.com/ialexisizotov-ctrl/ds-guard-xanmod/main/interactive.sh | sudo --preserve-env=SSH_CONNECTION bash
```

Русское меню предлагает полную установку, только ядро, ds-guard, сетевой профиль,
проверку, состояние, отключение, удаление и отмену управляемого обновления.
После переподключения запускается та же команда. Файлы проверяются
по закреплённым SHA-256 до исполнения. Без терминала установка и перезагрузка
автоматически не выбираются.

## Исправление мастера rc3

GRUB при закреплении ядра удаляет пустые `next_entry` и `prev_saved_entry`.
Прежняя проверка ошибочно считала это конфликтом уже после смены основного ядра.
Помощник теперь принимает только очистку этих пустых значений, сохраняя строгую
проверку остальных метаданных и принадлежности файлов.

Если закрепление остановилось в состоянии `confirming`, мастер заново проверяет
ядро, SSH и сеть и предлагает явно завершить операцию либо выйти.
Выход выбран по умолчанию. Когда нужное ядро уже назначено, повторная запись
GRUB не нужна. Из этой ветки не выполняются установка и перезагрузка;
переданный ранее `--mode` автоматически не продолжается.

## Неизменный основной комплект

Архив rc4 и его manifest остались прежними:

- Архив SHA-256: `b77dd6b4f11ac863f5c3fbc2a30c54b19ddb61a80eb646a96779ec49abfb552e`.
- Manifest SHA-256: `7389c5adf29a37360735e0351c22572fbf448d3a7ea918c6d6c1bfb5a71ff48c`.

Основной установщик получает недостающие зависимости из отдельных подписанных
индексов Ubuntu, проверяет план без замены прежних пакетов и учитывает
подтверждённое происхождение собственных пакетов при повторном запуске.
Защита первой установки Suricata сохраняется. При частичном dpkg-сбое и YAML
без исходной резервной копии запрет запуска остаётся, возврат считается незавершённым.

Документы внутри архива фиксируют прежний срез с мастером rc2 и не переписываются.
Этот README и файлы нового мастера проверяются по `WIZARD_SHA256SUMS`.
Корневой `SHA256SUMS` описывает состав основного комплекта, включая двоичные
файлы, и не является manifest нового README или всего рабочего дерева GitHub.

## Проверки и границы

Основной комплект: **256 локальных тестов** в ранее зафиксированной квитанции.
Для текущего мастера: **157 тестов**, проверка синтаксиса,
контрольных сумм и распаковки неизменного архива. Настоящий серверный бинарный
файл GRUB 2.12 проверен с временным каталогом загрузки:
очистка пустых одноразовых значений и сохранение
остальных метаданных подтверждены; рабочий grubenv не изменялся.

Полная установка и повторный запуск основного комплекта проверены на одном
сервере. Это не приёмка всех серверов, публичной подписки, мобильных клиентов
или непрерывной нагрузки. Прежние SSL/UDP-отказы сохранены в результатах;
последующий успех не объясняет их причину. Последующие результаты и точные
границы приёмки см. в описании релиза.

Новое ядро сначала выбирается для одной загрузки; перезагрузка требует
отдельного выбора. При зависании до systemd нужен независимый watchdog
или сброс через панель хостера. Безусловный автоматический возврат после
любого зависания не обещается. Старое ядро сохраняется.

Подробности: [интерактивный мастер](INTERACTIVE_RU.md),
[эксплуатация основного комплекта](OPERATIONS_RU.md), `WIZARD_VALIDATION.json`.
Стабильный `bootstrap.sh` остаётся отключённым.
